# Historical implementation plans

These plans record the design and implementation steps considered at the time they were written.
They are retained as evidence for past decisions, including plans for commands and mechanisms that have since been removed.
Do not use a completed plan as the current implementation procedure.

Current behavior is defined by the implementation and [specification](../../spec/spec.md).
Current work and acceptance status are tracked in GitHub issues and the [roadmap](../../../.pfdsl/roadmap.pfdsl).
The adjacent `specs/` directory has its own documents and is not classified as historical by this retention policy.

Keep historical plans unless a concrete maintenance problem requires moving or removing them.
A plan's size or obsolete feature names alone do not establish that it is unused evidence.
