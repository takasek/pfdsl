公開版 0.0.26 を握らせると、差分の散文が指すコマンドが存在せず、配布物の欠陥ではない行き止まりが大量に出る。
そこで作業ツリーの `packages/cli` を `npm pack` した tarball（同じく 0.0.26 を名乗る）を「次に公開される版」として各 sandbox に入れた。

公開時に CLI と plugin を別々に出す場合はこの前提が崩れる。

### レビューの指摘への対応

- 環境収集（`collect-report-environment.mjs`）の7件（`1d285f74` ほか）。
  - 理由文に宣言値を埋め込んでおり、`file:/Users/<name>/...` の宣言がローカルの絶対パスを公開 issue に載せる。宣言値を載せず、種別だけを書くようにした。
  - 壊れた `package.json` が「宣言なし」と区別できず、項目が黙って消えた。`unavailable` に載せるようにした。
  - 入っているパッケージ情報が読めない場合、Yarn PnP の場合、`optionalDependencies`、monorepo の下位パッケージ、作業ディレクトリが bundle の中にある場合を扱った。
  - テストが実行環境の上位ディレクトリを探索していた箇所に、探索器を注入した。
- 文言の3件。pfd-upstream-report の `repoCliVersion` の説明が plugin 構成でしか正しくなかった箇所と、この記録の Codex 版についての記述を直した。pfd-retro の適用単位の文は、下の設計変更で書き直した。

### 設計変更: 採用先の宣言を `.pfdsl/config.json` に置く（ADR-0042）

B の 1（`--deploy` で sweep workflow の採否を先に決められない）に対し、所有者は次を決めた。

- 配置したファイルは、チームや CI に届かせるには commit するしかないため、再配置のたびに sweep workflow は commit される。採否は workflow の有無ではなく、採用先が git 管理する `.pfdsl/config.json` の `sweepCompletedChains` で決める。宣言が無ければ workflow は通知だけを出して何もしない（`dbcba1f4`）。上流リポ自身は有効にした（`d7519576`）。
- 切り替えや列挙のような宣言の値は、読み手が agent であっても同じファイルに置き、binding はそのキーを指す。pfd-retro D 層の宣言も、公開前のこの時点で `knowledgeLifecycleAudit`（`mode` と `targets`）へ移した（`8ed858db`・`32700cbb`）。ADR-0041 は同日の設計続行として改訂した。
- 移行状態（#1319）の置き場所もこのファイルに予約した。実装は次回以降とする。

この変更で、B の 1 は解消した。移行ガイドの sweep の節と D 層の節は、config の形に書き換えた。
D 層の宣言の移設では、P1 系の probe が迷った「どの散文が監査対象の明示に当たるか」が、`targets` の配列として機械的に決まるようになった。
config の形そのものは probe で回し直していない。判定の網羅は `scripts/lib/knowledge-lifecycle-declaration.test.mjs` と `scripts/pfdsl/sweep-workflow.test.mjs` が持つ。
