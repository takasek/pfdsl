## 詰まりと分類

### (a) 配布プロンプトの欠陥

1. **pfd-retro の「適用単位」節が D 節と食い違っていた（P1a・P1c・P1d が独立に指摘）。**
   19行目が「宣言が無ければ対象の有無によらず非適用とする」のままで、D 節の「キーが無ければ毎回報告する」と両立しなかった。
   今回の probe は D 節を優先して正しく振る舞ったが、19行目だけを読めば黙って止まる。
   → `f3f570a0` で、19行目を「監査しないが、黙って飛ばさず D 節の規則どおりに報告する」に改めた。
2. **scaffold の説明文が値に依存していた（P1d）。**
   宣言行の下の説明が「上の行は…監査しない宣言である」で、値を `adopt` に変えると事実に反した。
   → `f3f570a0` で、値の意味を両方示す中立の文にした。
3. **環境収集がリポで固定した CLI の版を報告しなかった（P3）。**
   PATH 上の古い `pfdsl`（0.0.25）だけを `cliVersion` として報告し、リポが devDependency で固定した 0.0.26 は見えなかった。
   PATH の版を報告すること自体は preflight の挙動と一致するので変えず、`repoCliVersion` を併記する形にした。
   → `8e63e4ad` で追加したが、repo-local / upstream-checkout 構成でしか効かず、P3 の plugin 構成に届かなかった。
   → `a47d9b17` で、plugin 構成では作業ディレクトリの git top-level を採用先として読むよう拡張した。
4. **「毎回 Skipped」という症状から移行ガイドへの経路が無かった（P3）。**
   #1317 が `architecture.md` から回復手順を外した結果、報告者は既知の移行状態に対して新規 issue を下書きした。
   → `f3f570a0` で `architecture.md` の鮮度セルフチェック節にガイドへの案内を置いたが、再実行（R3）では読まれなかった。報告者は pfd-upstream-report の手順から installer のコードへ直行し、その節を通らない。

  教訓「課題文はスキルの述語をそのまま使う」の呼び出し形式版である。
