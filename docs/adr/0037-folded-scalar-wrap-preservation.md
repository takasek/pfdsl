# ADR-0037: frontmatter の所有は表現の正準化までとし、著者の改行意図は保存する

- Status: Accepted
- Date: 2026-08-10

## Context

ADR-0034 で `.pfdsl` frontmatter のフォーマットは pfdsl が所有すると決めた。
`fmt` / `meta set` / `sort` / `reindex` / `insert-definition` の5経路はいずれも `renderFrontmatterCst`（`Document.toString({ lineWidth: 0 })` による全文再直列化）を共有する形に統一された。

その帰結として、folded scalar (`>`) に手で入れた折返しが5経路すべてで1行に畳まれる。

```yaml
    description: >
      一行目。
      二行目。
```

main の fresh build で `fmt` と `meta set`（別ノードの `status` 更新）の両方が `一行目。 二行目。` へ畳むことを実測した。
`>` は YAML 仕様上、改行を値へ折り畳む記法であり、一度パースすると改行位置は値に残らない。
編集対象のフィールドを一切触らなくても、parse → toString の往復だけで失われる。

ADR-0034 はこの帰結を明示的に検討していない。
決定文は「既存ファイルは再整形される」とだけ述べており、再整形がどこまでを含むかの線引きがなかった。

PR #712 はこの現象をバグとして扱い、`node.range` を使ったバイト範囲スプライスで「触っていない箇所は元テキストのまま残す」方式を実装した。
production 728行・テスト845行・25コミットまで膨らみ、以下の理由で採用しない。

- ADR-0034 が削除した位置ベースの手術の再導入にあたる
- `fmt` を対象外にしていたため、`fmt` を通すと保存が取り消される。`make check-fmt` が運用 `.pfdsl` を canonical fmt で gate しているため、保存しても gate 通過時に消える
- `sort` の並び替えトリビア問題が最も高くつき、修正往復の主因になっていた

## Decision

**所有の範囲は表現の正準化までとし、著者が置いた改行位置は保存する。**

- **インデント幅は正準化する**。8スペースの継続行は `fmt` で2スペース基準へ揃う
- **改行位置は保存する**。`>` は valid な YAML 記法であり、見た目を折る意図があって書かれる。整形で潰してよい表現ではない

実装は `renderFrontmatterCst`（5経路の合流点）の後処理1箇所に置く。

1. 元の frontmatter YAML を再 parse し、`BLOCK_FOLDED` スカラーの path・生テキスト・composed value を集める
2. 再直列化後のテキストを parse し、同 path のノードが `BLOCK_FOLDED` かつ composed value が不変なら、元の継続行を新しいインデント幅へ再インデントして差し替える
3. 値が変わったフィールドと explicit indentation indicator (`>2` 等) を持つものは対象外とし、従来どおり再直列化する

`|` literal は改行が値に含まれるため元から保存されており、対象外。
シーケンス要素として書かれた folded scalar（`tags:` の項目等）も対象外とし、従来どおり畳む。
path をマップのキー列で引くため要素位置を辿らないが、その場合は差し替え自体を行わないので誤置換は起きない（実測確認済み）。
frontmatter の配列フィールドは短い文字列の列であり、折返しの需要がない。

## 検討したが不採用の案

- **畳むまま仕様として明文化する案**: `.pfdsl` 52ファイルにブロックスカラーは0件であり、ヘルプ文言と CLAUDE.md の記述規約を実挙動に合わせるだけで済む。最も安い。`>` は valid な記法であり、それを使って見た目を折るときには意図があるという判断で却下した。
- **バイト範囲スプライス（PR #712）**: 上記 Context の3点により却下。
- **`|` literal を使う規約にする案**: `|` は改行を値に含むため round-trip で保存される。ただし `>`（論理的には1行、表示上だけ折る）の意味を代替できず、記法の制限になるため却下。

## Consequences

- 長い `description` / `criteria` は `>` を使えば折返しを保ったまま書ける。frontmatter で改行を保つ手段が初めて実際に機能する
- インデントは正準化されるため、`fmt` は「著者の改行位置を保った上で正準形へ揃える」動作になる。canonical の定義が入力の改行位置に依存する形になるが、冪等性は保たれるため `check-fmt` は従来どおり機能する
- 折返しフィールド自身の値を `meta set` で書き換えた場合は再直列化される。書き換えた値に対して元の折返しを当てる根拠がないため
- 現行コーパスにブロックスカラーは0件のため、既存 `.pfdsl` への影響はない
- PR #712 の実装は破棄する
