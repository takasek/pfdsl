# ADR-0036: 配布層 probe の起動条件を公開境界に置く

- Status: Accepted
- Date: 2026-08-01

## Context

ADR-0029 は「配布層の欠陥は使い捨て環境での採用初日再現で検出する」を決め、4観点（同梱物妥当性・ガイダンス実行可能性・agent 到達性・冪等性）を定義した。
決定は正しかったが、**いつ回すか**が書かれなかった。

結果、2026-07-10（#352）に1回実施されたきりである。
`.claude/skills/` `.pfdsl/` `scripts/` `Makefile` `.github/` のいずれにも ADR-0029 への参照は無く、起動条件はどこにも存在しない。
pfd-retro の D 層が「休眠能力」として監査している型そのもの — 道具を作っただけでは気付き依存は解消されない。

その間に同じ欠陥クラス（配布散文が上流リポの文脈を前提にし、利用側で意味不明または実行不能になる）が繰り返し混入した。
#340 の修正 PR がその修正対象と同型の文言を新規に持ち込み、#674 として再度起票されている。
散文の規約（配布層に固有名詞・issue 番号・パスを書かない）は既にあり、効いていなかった。

ADR-0024 が同型の問題（能力に判定可能な起動条件が無い）を扱った先例であり、そこでも「たまったら」という基準点なしの条件を差分計測形へ書き換えている。

## Decision

**配布層 probe の起動条件を公開境界に置き、機械で強制する。**

- `plugin/pfdsl/.claude-plugin/plugin.json` の版を、probe 実行記録が記録した最新の対象バージョンと比較する。
- 記録が公開版より古ければ、cli リリースの pre-tag checks を失敗させる（`scripts/check-probe-currency.mjs`）。cli リリースが plugin bundle を出荷する経路であり、libs / vscode は該当しない。
- `make release-status` は同じ判定を非ブロッキングで表示する。

判定の意味は「probe は利用側が現に持っている bundle を歩いていること」である。
probe 後に1回出荷するのは許すが、2回目は許さない。

**サイクル境界には置かない。** 配布層に触れるコミットは日に複数回発生し、その頻度で probe を義務化すると「軽いタスクを与えて素早く記録を埋める」方向へ劣化する。
公開は稀であり、かつ利用側が実際に傷つく唯一の瞬間である。

## Rationale

1. **実績があるのは決定的な検査であり、agent probe ではない。** ADR-0029 の実行記録では、確定バグ #417（scaffold の repo-local 専用パス）を検出したのは観点1（grep 監査）である。観点3（fresh agent）は同じ回に「完遂した」と報告し、このバグを拾っていない。したがって観点1 の主要規則は静的検査へ移し（`check-bundle-paths.mjs`）、probe に残すのは静的検査が届かない観点2・4 とする。
2. **頻度が低いことが記録の質を守る。** 記録の存在は機械検査できるが、その回のタスクが問題箇所を踏んだかは検査できない。頻度が上がるほど形式的充足へ流れるため、起動条件の希少性そのものを設計要素として使う。
3. **既存の pre-tag checks に配線できる。** `scripts/release.mjs` は既に build / test / check-docs / gen-plugin identity を公開前に実行しており、新しいゲート機構を持ち込まずに済む。

## Consequences

- 現在の状態は失格である（probe は v0.0.19、公開済みは v0.0.24）。次の cli リリースは probe の再実施を要求する。これは意図した動作であり、5リリース分 probe なしで出荷されていた事実の可視化である。
- probe の手作業量は ADR-0029 執筆時より小さい。観点1 の repo-local パス規則は `check-bundle-paths.mjs` が毎 CI で検査するため、残るのは観点2（ガイダンス実行可能性）と観点4（冪等性）である。
- **捕まえられない残余**: 公開と公開の間に混入した欠陥は、次の公開まで検出されない。パスの形をしていない上流前提（Makefile ターゲット名・CLI サブコマンド名など「上流でだけ叩けるコマンド」）は静的検査も probe も構造的に保証しない。
- 検討して却下した案を記録する。**配布散文中の全パスを利用側ビューで解決する検査**は、対象コーパス 137 件のうち約 100 件（73%）が正当な除外対象（`.pfdsl/` 配下・プレースホルダ・スラッシュコマンド・正規表現アーティファクト）であり、除外ロジックを積むほど `check-bundle-paths.mjs` の語彙的部分集合へ縮退する。加えて非パス形の上流前提を原理的に検出できない。
- ADR-0029 は撤回しない。手法の決定はそのまま有効であり、本 ADR はその起動条件のみを追加する。
