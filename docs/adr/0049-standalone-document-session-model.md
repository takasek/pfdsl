# ADR-0049: standalone の文書セッションを対象別観測と操作計画で表す

- Status: Accepted（#1431 で実装。Mac 実機の再受入は所有者が担当）
- Date: 2026-10-12
- 対象: #1258、PR #1431

## Context

standalone アプリの `DocumentSession` は、保存先・観測・回復の状態を重なり合う可変フィールドで持っていた。
具体的には `disk`・`observed`・`conflict`・`pendingTarget`・`sourceConflict`・`saveFailure`・`uncertain`・読取失敗の記録・`observationVersion` であり、入口（poll、Save、close/quit、Review and Save Here、Use Current Disk Version、再オープン）ごとに異なる部分集合を読み書きしていた。

PR #1431 のレビューでは、外部レビュー bot が約10周にわたり1周1件ずつ欠陥を指摘した。
最終周の観点1〜4と別モデルによる独立解は、同じ形の欠陥をさらに見つけた。
保存対象の取り違え、パネルの表示とボタンの操作対象の不一致、承認した内容と保存した内容の不一致、回復先の監視漏れ、入口ごとに異なる読取失敗の扱い、終了承認後の編集の保存、古い回復先表示の残存である。
個別修正はそれ自体が退行を2件生み、修正のたびにフィールドと分岐が増えた。
欠陥は個々の分岐ではなく、状態の書き手が複数あることから生じている。

## Decision

### 状態

セッションが保持する状態を次の4つに限る。

1. **承認済みの基準**（acknowledged）：editor に承認済みとして入っている本文と、それに対応する生のディスク snapshot。open・保存成功・明示的な採用（Use Current Disk Version）・clean な editor の自動再読込でだけ更新する。
2. **対象別の観測**（observations）：追跡する対象ごとに `readable(snapshot)`・`missing(snapshot)`・`unreadable(error)` のいずれか。追跡する対象は、active 文書の native binding と、未解決の回復先だけである。表示パスは観測した snapshot から取る。
`unreadable` は、対象の識別とパネルでの名前・直前の本文の表示のために、直前に観測した snapshot を保持する。
これは読める現行版の証拠としては使わず、保存・採用の前に対象を再検査する。
保存の応答から作る `unreadable` は snapshot を持たず、パネルのボタンも無効のままにする。
3. **未解決の保存**（recovery）：失敗または未確認の保存の対象と receipt（publication の既知/未知を含む）。成功するか、明示的に解決されるまで保持する。
4. **世代**（epoch）：観測の分類（readable・missing・unreadable）・内容（同一内容判定で比較）・表示パスが変わるか、対象を初めて観測するたびに1つ進む。

衝突の有無、dirty 表示、パネルの表示内容と対象名、元文書の変更通知、終了判断の照合値は保持せず、上の4つから導く。
再オープンで native capability を更新する場合は、承認済み本文を変えずに基準と観測の対象 ID・binding・パスを付け替える。
内容の比較は、生のディスク本文の一致か revision の一致で行う（`sameDiskContent`）。
UI の判断は内容の同値性で行い、native の保存は承認した厳密な revision と保護メタデータで検査する。

### 観測の単一入口

poll、Save 前の読取、close/quit の再検査、Use Current Disk Version の再検査、再オープン時の capability 更新後の観測適用は、すべて同じ `observe(target, result)` を通す。
再オープンの移動回復判定で行う旧 leaf の検査は、失敗すれば capability 更新を許可せず、セッションへの観測適用は行わない。
同じ観測結果は、入口にかかわらず同じ保護状態を作る。
各対象は独立に読み、ある対象の失敗で他の対象の読取を省かない。
clean な editor（本文が承認済み基準と一致し、未解決の保存がなく、active 対象の直前の観測が基準と同内容）が読める別内容を観測した場合に限り、自動再読込して基準を更新する。
保存成功は、その対象の観測を `readable(result.current)` に置き換え、観測が変われば同じ判定で世代を進める。
終了処理は Save 成功後の照合値を記録して最後の再検査と比較するため、成功した保存だけを理由に終了の2回目の試行を要求しない。

### 操作計画

保存・再作成・採用・終了の確認は、1つの関数が作る操作計画を経由する。
計画は、操作の種類、対象、送る revision、ダイアログに表示するディスク本文と editor 本文、計画作成時の世代と editor の版を持つ。
ダイアログは計画から描画する。
実行時に世代と editor の版を照合し、変わっていれば実行せず本文を保持して再判断を求める。
保存要求には計画の本文と revision をそのまま渡す。
close/quit の Save は終了確認の計画を保存処理まで渡し、Save 前の読取の後、本文を取得する前に照合する。

## README の保証と構造の対応

| README の保証 | 構造上の担保 |
|---|---|
| dirty な変更・削除・公開時の衝突は本文を保持して確認に回す | dirty は基準・観測・回復から導くため、入口ごとの判定差がない |
| 確認は、確認を求めた時点の editor とディスクの状態にだけ適用する | 操作計画の世代と editor の版の照合 |
| Replace は確認で表示した版を使う | 保存要求は計画の本文と revision をそのまま送る |
| パネルは、ボタンが操作する対象と同じ観測を比較に使う | パネルの対象名・比較本文・ボタンの対象を同じ観測から導く |
| 未解決の対象はそれぞれ独立に読み、1つの失敗で他を省かない | 対象別観測と単一入口 |
| 読めなくなった旧ディスク版の生存 editor 本文は確認を要する | `unreadable` 観測が dirty を導く。入口にかかわらず同じ |
| 同一内容の変化はディスクの変更として扱わない | 世代と衝突の判定は `sameDiskContent` による |

## 検証

不変条件は、harness が自分で記録した観測（表示したダイアログとその本文、送った要求、fake native のファイル内容、editor 本文、パネルの DOM、タブの存否、要求と応答と判断と破棄の順序）だけで定義し、セッションの内部状態を読まない。
状態 × ディスク側の変化 × タイミング × 操作の直積と、多段の失敗履歴・対象関係の変化を含む回復状態の直積に当てる。
検査は `packages/standalone/test/document-lifecycle-*.test.mjs` と `test/helpers/lifecycle-invariants.mjs` にある。
src を壊す変異 M1〜M13 のそれぞれを不変条件に紐づくセルが検出することを、`test/helpers/mutation-gate.mjs` で確認する（`make test` には含めない）。
改修前の head で見つかっていた欠陥（独立レビューの F1〜F4、観点1・2の N2）は、改修前は既知の失敗として記録し、改修で解消する。
native 側の保存契約、新規ファイルの mode、native の競合直積は変更しない。

## Consequences

- `DocumentSession` の内部フィールドに依存していた単体テストは書き直す。固有のシナリオ（ハードリンクの別タブ化、元 leaf の消失を確認した inode による rename 回復、混在改行と Monaco の正規化、Save As の採用拒否、恒常的な読取失敗のもとでの明示 Discard）は、host を通す検査へ移植してから消す。
- 以前の head に対する所有者の Mac 実機受入は、保存経路の再構成により新しい head へ転写しない。全保存経路の再受入が必要になる。
- 最終観測後の外部変更を原子的に排除する保証、compare-and-swap、履歴、クラッシュ復旧は従来どおり提供しない。

## 却下した案

- **入口ごとの個別修正を続ける**：この PR で実際に退行を生み、フィールドと分岐を増やし続けた。独立レビューの2周目も、観測の記録入口・回復対象の遷移・確認世代の照合の共通化を求めた。
- **衝突中の通常 Save を回復パネルへ誘導するだけにする**：パネル自体が複数のフィールドを参照しており、監視漏れも残る。
