# ADR-0052: pfd-ops の `install/` をリポルートの正本から生成し、配布対象を明示的に列挙する

- Status: Accepted
- Date: 2026-11-03
- Partially supersedes: ADR-0016 の、`install/` を編集の起点として deployed へ複写する向きと、配布対象を列挙しない方針

## Context

本 ADR は、2026-07-26 に実装した決定を後から記録する。

ADR-0016 は、採用先へ配布するファイルを `.claude/skills/pfd-ops/install/` に集約した。
`install/` 側を canonical、リポルートの同じ相対パスにあるファイルを deployed とし、CI で両者の一致を強制した。
配布対象は `install/` の下に置くことで決まり、配布対象の列挙は「ファイル追加時の更新漏れが構造的に発生する」として却下した。
ADR-0016 と ADR-0028 の canonical は、採用先へ配布するテンプレートを指す。
本 ADR では、それと区別して、手で編集する版を正本と呼ぶ。

このリポで実行され、テストが import し、import の検査が対象にするのはリポルート側のファイルである。
そのため編集はリポルート側から始まり、canonical への複写だけが手作業で残った。
2026-07 に、リポルート側だけを直した修正で複写を忘れ、CI の一致検査が落ちた。
一致検査が落ちなければ、修正前の版が配布されるところだった。

同じファイルの3つ目の複製である plugin 同梱物は、既に `install/` から生成し、生成結果との一致を検査していた。
手作業が残っていたのは canonical と deployed の組だけである。

最初に採った方針は、どちらの側を stage したかで同期の向きを決める双方向の同期だった。
実装と検証まで終えたが、乖離が起きる構造を残したまま新しい規則を4つ（双方向の同期・stage した側による向きの判定・両側を stage して内容が異なるときの停止・自動 stage）持ち込むため、マージせずに置き換えた。
この置き換えから作業手順に加えた規則は ADR-0033 が記録している。

## Decision

1. リポルートのファイルを正本とし、手で編集するのは正本だけにする。
   `install/` は正本から一方向に生成するミラーとし、手で編集しない。
   生成の向きは、正本から `install/`、`install/` から plugin 同梱物への一本になる。
   採用先へ配布するテンプレートは、引き続き `install/` とそれを同梱した plugin である。
2. 配布対象は、リポルートからの相対パスを明示した一覧で指定する。
   一覧への追加を「このファイルを配布する」という判断として扱う。
3. ADR-0016 の相対パスを保つ配置と、CI による正本と `install/` の一致検査は維持する。
   そのうえで、`install/` が生成の出力と一致することを検査し、一覧にないファイルが `install/` にある状態や、一覧にあるファイルが `install/` に無い状態を通さない。
   一覧と `install/` の実体が一致することも検査する。

## Rationale

1. **乖離の種類が1つになる。**
   向きが1つしかないので、起こりうる乖離は再生成のし忘れだけになる。
   これは plugin 同梱物と同じ「再生成して差分を見る」検査で捉えられ、双方向の同期に要る判定規則は要らない。
2. **正本を、いま実際に編集している側に置く。**
   編集する場所は変わらず、実行もテストもされないファイルを先に直す手順は生じない。
3. **配布対象を持つ場所が別に要る。**
   正本のディレクトリには、配布しないリポ内のテストが同居するため、ディレクトリ単位では配布対象を決められない。
   ADR-0016 では `install/` の中身そのものが暗黙の一覧だったが、生成物になった `install/` はその役を持てない。
   明示した一覧があれば、リポ内向けのファイルを足したときに黙って配布されることがない。

ADR-0016 は列挙を「ファイル追加時の更新漏れが構造的に発生する」として却下した。
本 ADR の一覧は生成の入力であり、一覧と `install/` が食い違えば検査が落ちる。
配布すべき新しいファイルを一覧に載せ忘れる漏れは残り、検査が捉えるのはその一部である（Consequences）。
暗黙の一覧では、リポ内向けのファイルが黙って配布される。
明示した一覧では、漏れは配布されない誤りとして現れる。
この2つのうち、配布されない誤りの側を選んだ。

## 却下した代替案

- **双方向の同期**: Context のとおり、乖離が起きる構造を残したまま新しい規則を4つ要する。
- **`install/` を canonical のまま手で複写する（現状維持）**: 複写忘れを CI が事後に検出するだけで、事前には防げない。
- **`install/` 側を先に編集する運用**: 実行もテストもされないファイルを先に直させる。
- **ディレクトリ単位で配布対象を決める**: 配布しないテストが配布対象に混ざる。

## Consequences

- 本 ADR は、ADR-0016 のうち `install/` を編集の起点として deployed へ複写する向きと、配布対象を列挙しない方針（Consequences 第1項「列挙不要」と、却下した代替案「ファイルごとに配布対象を明示」）を置き換える。
  配布テンプレートとしての `install/`、相対パスを保つ配置、CI の一致検査、composite action を使わない判断は、ADR-0016 と ADR-0032 のとおり存続する。
- 配布対象を増やすには、正本をリポルートに置き、一覧に加えて `install/` を再生成する。
- 一覧にある `.mjs` が相対 import するファイルを載せ忘れると、生成器が生成を拒否する（2026-09-05 に追加した検査）。
  どこからも相対 import されない入口スクリプトや、`.mjs` 以外のファイルの載せ忘れは検出されない。
  その場合、そのファイルを呼ぶ配布物（workflow 等）が採用先で壊れる。
- 採用リポへの配布経路（ADR-0028）と、配布物を置くディレクトリ（ADR-0032）は変えない。
