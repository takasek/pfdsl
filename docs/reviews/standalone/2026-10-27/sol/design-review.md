# デザインレビューと改善提案

保存版注記：pfdsl に関する部分を抜粋し、その結論・優先度を保持した。絶対パスと資料リンクを保存先に合わせて加工した。収録していない根拠へのリンクは「原本限定資料」と表記する。原文のフォルダ・同梱への言及は全原本フォルダを指す。非リンクの相対ファイル名も、provenance.json の収録一覧にない場合は原本限定資料を指す。


ソースと図を並べて扱う基本構成は有効で、主要な編集能力も揃っている。日常作業で優先すべき改善は、新機能の数より「問題のある場所へ気づいて移ること」と「編集中に参照していた関係を失わないこと」である。今回、データ消失や保存破壊は観測していない。P0 は挙げない。

P1 は日常の修正・確認を阻むため先に扱う項目、P2 は領域・操作の読みやすさを整える項目、P3 は仕上げの検討候補。優先順位は1評価者の観察による提案であり、人間一般の所要時間や頻度を測った結果ではない。

## 判断に使った一次資料

2026-10-27 に Apple HIG の [Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)、[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[Typography](https://developer.apple.com/design/human-interface-guidelines/typography) を取得した。長時間作業の快適な密度、キーボードとメニューバー、幅に応じた操作の整理、文字の読み取りと階層を基準にした。macOS の13pt/10ptという値を CSS px の合否線へ換算していない。HIG 全体の適合監査でもない。


提供された reference pack の README / galleryを読み、OmniGraffle の作業領域と VS Code の並列編集の図を確認した。前者からはキャンバス・全体操作・対象の属性の役割分担、後者からはペインの識別と文書の現在位置を比較した。古い図の外観、色、機能数をそのまま模範にしない。過去の pfdsl レビュー本文や他チャットの成果物は読んでいない。

## 確認できた長所

- Start は New / Open… / Try a sample の3入口と短い説明で簡潔。短いサンプルが直ちにソースと図を示す。最初の学習材料として良い。
- ソース・図・診断が常に同じ大枠にある。ノード選択はソースカーソルを動かし、検索や F8 の診断移動も図と開いている Connections に反映した。
- Connections は入力・中心・出力を左右に並べ、成果物の四角とプロセスの丸を保つ。単なる一列の属性一覧より前後関係を読める。
- Create definition は空の label を挿入して編集位置へ移し、そのまま入力するとラベルが図へ反映した。往復に必要な操作が短い。
- Fit と Focus selected node が既にある。13ノードの全体表示21%から対象を選び、Focus selected node で100%へ戻せた。新しい「選択へズーム」機能を重複提案しない。
- ネイティブ File / Edit / View メニューと標準保存ダイアログがある。Save As と Command-S による保存、ファイル bytes、タイトル・タブ・保存先・Saved の表示を確認。Recent から同じ文書を再オープンできた。
- 変更済み文書を閉じる確認は Save / Discard / Cancel。Cancel でバッファとタブを保持した。未保存の印は色だけに頼らず文字・点でも示す。

## D1 — 診断の件数から問題の場所へ移れる入口を作る（P1）

**観察事実**: 13ノードの文書は下部に6 warningsを示すが、そこには警告内容・行・移動の入口が見えない。F8 を知っていれば「1 of 6 problems」、具体的な W002 と9:3へ移れ、図も sources に追従した。F8 は評価者が既知の Monaco 操作として試したもので、画面が教えたわけではない。

**影響する作業**: 文書を開き、警告を順に確認して修正する作業。能力があっても、件数だけ見た利用者が次に何をすればよいか読み取れない。

**根拠**: [実操作 T6](task-log.md)、`medium-check.json` の6件。実装は [main.ts:145](https://github.com/takasek/pfdsl/blob/d1b5db85ecdb9344a5ed6fff2f1b17632a8ec6e6/packages/standalone/src/main.ts#L145) で診断 summary を status 要素へ入れ、[document-tab.ts:312](https://github.com/takasek/pfdsl/blob/d1b5db85ecdb9344a5ed6fff2f1b17632a8ec6e6/packages/standalone/src/document-tab.ts#L312) は Monaco marker を設定している。問題移動の新エンジンが必要という所見ではない。HIG のキーボード・メニューからの操作発見と情報階層に関係する。

**改善方向**: 件数を「問題を確認する」入口とし、クリック・キーボードで既存 marker の最初／次の項目へ移る。Edit メニューと表示中の案内にも次／前の問題を出す。大量一覧パネルを最初から追加する案より、既存能力への導線を先に整える。

**受入の目安**: ショートカットを教えずに6警告のうち指定した問題を見つけて直せる。現在の文書・フォーカス・図との同期を保つ。件数0のときも状態が明瞭。

**未確認**: 初見の人間がどの入口を選ぶか、VoiceOver、複数エラーの同時発生、標準 Monaco メニューの全動線。

## D2 — エラー修正中に関係を参照する文脈を保つ（P1）

**観察事実**: `result >> design` で循環を作ると V010 と該当ノード名が表示される一方、図は消え、Fit・ズーム・Connections が無効になった。開いていた Connections も閉じる。`>>?` に直すと図と操作が戻る。

**影響する作業**: 複数エッジを直しながら、どの入力がどこにつながっていたか確認する往復。エラー説明自体は具体的だが、修正のための図が同時に使えない。

**根拠**: [再現 T3](task-log.md)、実画面（原本限定資料）、[AX](evidence/native-cycle.ax.txt)。[preview.ts:805](https://github.com/takasek/pfdsl/blob/d1b5db85ecdb9344a5ed6fff2f1b17632a8ec6e6/packages/editor/src/preview.ts#L805) の showError は選択と編集データを消し、図を隠して inner を空にする。現在の設計が不正なソースへの図編集を止める点は維持すべき長所である。

**改善方向**: 最後に妥当だった図を参照専用で残す小さな試作を推奨する。「現在のソースにエラーがある／この図は最後の妥当な版」という表示を常時出す。古いノードから現在ソースへ無条件で移動・編集しない。代案は図を残さず、エラー一覧と問題箇所への移動を充実させる方式。誤った最新図と取り違えさせないことを優先し、実作業の比較で選ぶ。

**必須条件**: 古い図の表示を通知の一種にして一時的に消さない。保存成功や通知の取消でエラー・鮮度の状態を消さない。初回から不正で「最後の妥当な図」がない場合を説明する。図の旧版と現在文書の対応が保証できない操作は止める。


**未確認**: 保存中の競合や非同期解析の順序、大規模図のメモリ費用、履歴図が実際の修正速度を改善するか。現在の無効化を単に撤去する変更は提案しない。

## D3 — 狭幅の Connections を読み取れる構成へ変える（P2）

**観察事実**: ブラウザ幅600px・左右50%では、Connections の見出しが単語の途中で折れ、中心の design も分断され、接続入力の案内が短くなる。800pxではツールバーが折り返すが操作は残った。600px画像（原本限定資料）。

**影響する作業**: ほかの資料と並べた半幅ウィンドウで、ノード名と入力・出力を照合する作業。

**根拠**: [preview-shell.ts:48](https://github.com/takasek/pfdsl/blob/d1b5db85ecdb9344a5ed6fff2f1b17632a8ec6e6/packages/editor/src/preview-shell.ts#L48) の三列 grid と anywhere 折返し。幅不足でも三列を維持する。HIG の快適な密度と幅への適応。提供された OmniGraffle の図は役割分離の参考であり、この三列を常時守る理由にはならない。

**改善方向**: 狭い図領域では、見出しを独立した行に置き、入力／中心／出力を縦に読める構成に切り替える。キャンバスを圧迫するなら折畳み可能な専用の詳細領域にする。ソースの幅変更も既存 splitter を使えるが、利用者に毎回調整を要求する回避策だけにしない。

**受入の目安**: 600pxと800px、長い英語／日本語の label、入出力が複数のノードで、名前・方向・編集対象を途中分断に頼らず読める。popup とキーボード操作を残す。

**未確認**: ネイティブで同じ幅にしたときの最小幅と挙動。幅の境界値は実装前に実測で決める。

## D4 — 全体表示と対象を読む操作を一組として見せる（P2）

**観察事実**: 13ノードを Fit すると21%になり、全体構造は見えるが文字は読みにくい。対象選択後の Focus selected node は100%に戻り有効だった。小さな枠ボタンが連続し、ズーム・Fit・Actual size・Focus selected node・Connections・Help の役割が視覚的に分かれない。幅変更後は図の一部が画面外になり、Fitで戻せる。

**根拠**: 全体表示（原本限定資料）、対象表示（原本限定資料）。[preview-shell.ts:13](https://github.com/takasek/pfdsl/blob/d1b5db85ecdb9344a5ed6fff2f1b17632a8ec6e6/packages/editor/src/preview-shell.ts#L13) の同じ12px、同じ border、4px gap。[preview.ts:583](https://github.com/takasek/pfdsl/blob/d1b5db85ecdb9344a5ed6fff2f1b17632a8ec6e6/packages/editor/src/preview.ts#L583) の resize は初回以外に全体 Fit をしない。ユーザーの倍率やパンを保存する意味があり、毎編集の自動 Fit は対案として採らない。

**改善方向**: ズーム／全体・対象への移動／Connections の表示を間隔やグループで区別する。既存 Fit と Focus selected node の役割を短いラベル・tooltip・メニューで一緒に教える。選択なしのときは対象を選ぶ案内を出す。幅変更では倍率を保ちつつ注目点を新しい領域内に保つ案を比較する。

**受入の目安**: 機能を事前に教えず、図全体を確認して指定ノードを読める倍率へ戻せる。手で調整したパンや倍率を毎回奪わない。toolbar の狭幅処理は単なる折返しだけでなく優先順位を持つ。HIG Toolbars の論理的グループと過密回避に対応する。

**未確認**: 100ノード以上の操作、大きな日本語ラベル、倍率を変えたときの読取り性能、ホイールの精密な挙動。パンとボタン拡大は確認したが、トラックパッドのピンチは未確認。

## D5 — 図と周辺 UI の書体を一体として検討する（P3）

**観察事実**: UI は sans、ソースは monospace、図は serif。小さなサンプルでは読めるが、別由来の部品を組み合わせた印象が強い。13ノードの21%表示では書体を変えるだけで読めるようにはならない。

**方向**: 図の英語・日本語 label と ID の階層を、画面表示向けの少数の書体で比較する。まず D4 の倍率と対象移動を整え、その後に100%表示で長いラベルを評価する。serif 自体を HIG 違反とはしない。出力される SVG/PDF の見た目に影響するため、画面用と書き出し用の意図を決めてから扱う。

**未確認**: フォント fallback、コントラスト実測、ダークモード、書き出し、視力や閲覧距離の違い。好みと可読性の実測を分ける。

## 第一印象から変わった理解

最初は文書操作の入口が消えるように見えたが、ネイティブではメニューバーが主入口として機能していた。ブラウザだけを見て「開く／保存がない」と評価しない。保存状態とパスが離れているという印象も、実際にはタイトル・タブ・完全パス・保存メッセージが対応していたので、文書識別の大改修を優先しない。

同様に、全体図の文字が小さいことから新しいズーム機能を要求しかけるのではなく、既存 Focus selected node と Connections を確認して、導線と階層の問題に絞った。実装を読むとエラー時の消去は意図的な編集無効化も担っていると分かり、単なる表示保持から「古い図を安全に参照する設計」へ提案の条件を変えた。
