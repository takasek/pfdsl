1. ソースと図に、用途に合った幅を渡す

観測空の一覧も約227 CSS pxを占めています。1280px幅では残り1053pxのうちソース350.89px、図702.11pxでした。800px幅ではソースが約191pxまで狭まり、日本語の定義を横に追う負担が増します。固定的な分割を作業内容に合わせて変更する入口はありません。測定値、狭い幅の表示 [参照資料はこの保存版に未収録]。

実装packages/standalone/src/style.css:104には両方50%とありますが、図のコンテナに付くクラスのpackages/editor/src/preview-shell.ts:4がwidth:100%を指定しています。ブラウザで観測した約1:2の比率を説明できます。「現状は均等分割」と評価してはいけません。

提案まずスタイルの責務を明確にし、ユーザーが動かせる分割線を設けます。Source / Split / Diagramとサイドバー表示切替をViewにも置き、図だけの状態からノードのソース移動を選ぶと、ソースを再表示して該当行へフォーカスを戻します。比率変更と表示切替で編集履歴・カーソル・図の視点を失わないことを受入条件にします。

Apple HIG: Split viewsのmacOS向けの幅調整・ペイン表示制御と、Designing for macOSの長時間の作業・調整可能な作業領域を根拠にしています。参考S01 OmniGraffleからは「中央の内容に周辺の操作を従わせる役割分担」、S04 VS Codeからは「並列領域を独立に扱う構造」を学びます。色や固定比率を移植する提案ではありません。

2. 「Saved.」の対象と鮮度を明らかにする

観測ある文書を保存後、別のWelcomeタブへ移って編集しても、ヘッダーには「Saved.」が残りました。タブの未保存ドットと並ぶため、今の文書が保存済みだと誤読する余地があります。データ消失を確認した指摘ではありません。別タブへの切替記録、未保存ドットとSaved.の同居 [参照資料はこの保存版に未収録]。

根拠の区別：収録したAX記録ではWelcomeが選択され、未保存ドットは非選択の文書にあります。AX記録が示すのはタブ切替後にも「Saved.」が残ることです。上記のWelcome編集後の記述は、元資料の画像08-native-error.pngに基づきます。この画像には選択中のWelcomeの未保存ドットと「Saved.」が同居していますが、公開保存版には画像を収録していません。

実装保存結果は単一のstatusへ書かれます（packages/standalone/src/main.ts:442）。タブ切替は表示と競合欄を更新しますがstatusを更新せず（同ファイル89行）、編集時もタブ名の更新です（143行）。

提案現在の文書名に添えて「Edited」「Saved」「Changed on disk」を表示し、過去の操作結果は「Saved A.pfdsl」の一時通知として区別します。保存処理中に別文書へ移る場合も、結果を元の文書へ帰属させます。エラーや外部変更の操作は対象パスを示し、取消後も編集内容と未解決状態を保持します。

受入例は「A編集→A保存→Bへ切替→B編集」「同じAを保存後さらに編集」「保存中に切替」「外部変更の確認を取消」です。前2例の帰属の違いは現状モデル [参照資料はこの保存版に未収録]と提案モデル [参照資料はこの保存版に未収録]で比較できます。条件を手動選択する模型であり、実ディスク処理の保証ではありません。

3. 既存操作を、macOSのメニューにも置く

観測実機のFileメニューにあるのはClose Window / Close Allで、New / Open / Saveがありません。Fileメニューの記録。一方、コードにはCmd/Ctrl+SとShift付きのSave Asが実装されています（packages/standalone/src/main.ts:611）。「キーボード保存がない」という指摘ではありません。

提案FileへNew、Open、Save、Save As、文書を閉じる操作、Editへ既存の整形、Viewへペイン表示とズームを配置します。ボタンと共通の処理を呼び、処理中や文書なしの有効・無効を一致させます。Close Windowと文書タブを閉じる操作は区別して、未保存確認を壊さないようにします。

Apple HIG: Designing for macOSはアプリのコマンドをメニューバーから見つけられることとキーボード操作を重視します。Menusの動作を予測できる名称も適用します。Tauri/WebViewでも適用できる入口の改善であり、全面的なネイティブUIへの書換えを前提にしません。

4. 文書操作・表示操作・検査を分け、エラーから戻れるようにする

観測NewからNormalized edgesまで8個のボタンが同じ強さで横並びです。幅不足では折り返し、statusも常時一行を使います（packages/standalone/index.html:5、packages/standalone/src/style.css:15）。ソースの構文エラーでは図が「L002: Unexpected character '-'」へ置き換わり、図の操作が無効になります。エラーメッセージから修正位置へ直接移る入口は、その表示では確認できませんでした。

提案上部は文書名と頻用のOpen/Save、表示操作を少数のまとまりに整理します。Format flows / Format flatは既存の2方式としてメニューに残し、Normalized edgesは読取専用の検査として分けます。構文エラーは行・列と「Go to error」を持ち、図を表示できない状態を明記します。古い図を表示する方式を選ぶなら、最新でないことを常に分かるようにする必要があります。

Apple HIG: ToolbarsとLayoutの頻度・まとまり・情報階層を根拠にします。右クリックのNode actionsでは「このprocessへの入力」「このprocessの出力」など意味を先に示し、矢印記法を補助にすると方向を確認しやすくなります。既存の不正接続防止と説明を弱める理由にはしません。

5. 初期状態と文書の識別を整える

観測起動時にWelcomeと日本語の例が2文書開きます（packages/standalone/src/main.ts:619）。サイドバーはRecent / Folder filesの見出しを持つ一方、初回は中身がありません。文書名はタブに出ますが、ウィンドウのタイトルはアプリ名中心です。本文・ボタン・一覧見出しはほぼ同じ文字サイズで、視覚上の役割差が弱めです。

提案初回にはNew / Open / Try sampleを選べる入口を置き、サンプルを利用者の文書と区別します。作業中は文書名と親フォルダを識別できるようにし、同名ファイルや長い名前は省略表示だけに頼らず確認できる入口を用意します。全体を大きくするより、文書名・本文・補助情報の階層を決め、エディタの文字拡大を試せるようにします。

Apple HIG: TypographyのmacOS値はpt単位であり、CSSの13pxをそのまま適否判定に使いません。Accessibilityに照らしたVoiceOver、フォーカス、拡大、コントラストは別途実測が必要です。シンタックスハイライトはREADMEで未実装と明記されており、現在機能の故障ではなく将来の読みやすさ改善として扱います。

残したい良さ

  • ソースを編集してすぐ図へ反映されること、図とソースの対応を辿れること。表示切替を加えてもこの往復を中心に置きます。
  • Normalized edgesは文書ごとの非モーダルな読取結果です。実機でタブ切替による非表示・再表示とEscapeによる閉じる操作を確認しました。起点へのフォーカス復帰と編集時のクリアはpackages/standalone/src/normalized-edges.ts:18などで確認しています。大きな画面遷移へ変える必要はありません。
  • 既存producerを持つreleaseへの接続候補は無効になり、IDを直接入力した場合もV001の説明付きで拒否され、ソースは変わりませんでした。不正接続の記録。新しい見せ方でも、この具体的な防止と理由を保ちます。
  • 自作テストファイルが元の場所からなくなった時、バッファと未解決表示を保ち、Use diskを無効にしていました。ファイル不在時の記録。これは一つの経路の観測であり、競合処理全体の受入完了ではありません。
