- **インターフェースの存在が、対象への到達可能性の証拠として読まれる trap**: 外部システムの API や tool schema が対象識別子を受け取る形を持つと、その識別子が指す対象へ現在の接続から到達できるように見える。
  schema が述べるのは呼び出しの形であり、接続先が保持する対象集合やセッション所有権ではない。
  対象自体が別の場所で生きていることを確かめても、そのインターフェースから到達できることの証拠にはならない。
  問いの形: 「この API が『使える』と判断した根拠は schema の形か、対象へ実際に到達した疎通結果か。対象の存在と、現在の接続からの到達可能性を分けて確かめたか」。
  具体例: ユーザーが `codex://threads/<uuid>` を提示し、MCP で直接やりとりできないかと尋ねた。`mcp__codex__codex-reply` の schema に thread ID で会話を継続する形があることから「できる」と断定して実行したが、`Session not found` が返った。writer lock は実在してスレッド自体は生きていたが、MCP server が保持する対象集合には入っていなかった（PR #1036 のレビューサイクル、#1037 で記録）。
  対策: 外部システムへの接続能力は、schema の存在でなく対象を指定した最小の疎通で確かめてから答える。疎通に副作用があり事前確認が必要なら、能力を断定せず「試さないと分からない」と述べ、確認後に試す。
