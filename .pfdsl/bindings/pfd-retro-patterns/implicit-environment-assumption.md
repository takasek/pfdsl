> 過去事例（保存基準: 33878aeb）。本文の対策・判断は当時の記録であり、現行の指示ではない。現行手順は [pfd-retro binding](../pfd-retro.md) を参照。

- **実行環境の暗黙前提 trap**: リポの運用スクリプトや CI が外部 CLI・配布バイナリ・ホスト機能の存在や権限を暗黙の前提にしていると、別のセッション種別や OS では処理本体へ到達する前に止まる。開発ホストでの成功は、CI runner の実行条件を検証しない。
  問いの形: 「この処理が前提にしている外部実行物とホスト機能は、全ての起動元セッション種別・対象 OS で利用でき、必要な権限と起動モードを満たすか」。
  具体例: `scripts/cycle-status.mjs` / `scripts/gate-check.mjs`（内部の `audit-issues-flow.mjs`）が `gh` に `execSync`/`execFileSync` で依存しており、`gh` 不在の Claude Code Remote セッションで `audit-issues-flow.mjs` が `spawnSync gh ENOENT` でクラッシュし、gate-check の残り項目の出力ごと失われた（#482 セッション、#489 で追跡）。
  具体例: VS Code webview smoke test は macOS の実 VS Code で通過したが、Ubuntu CI では展開された Electron の `chrome-sandbox` が root 所有・mode 4755 でないため CDP 起動前に `SIGTRAP` で終了した。Linux runner だけ明示的に `--no-sandbox` を渡し、platform 分岐を直接テストして解消した（#891）。
  問いの形の追加: 「その外部実行物は、検証した環境と本番の環境で**同じ版に解決されるか**。解決元が違うなら、今回足した能力はどちらにも入っているか」。存在・権限・起動モードが揃っていても、同名のコマンドが別の版へ解決されれば能力集合が違う。不在は最初の呼び出しで露見するが、版差は**その版に無い部分を使うまで**露見しない。
  具体例: 回収スクリプトが `pfdsl delete` を呼ぶ。CLI の解決順は「環境変数 → リポの `packages/cli/dist/cli.js` → `node_modules` の公開版」で、開発ホストでは常に第2候補が当たっていた（ローカルで build 済みのため）。CI には `dist/` が無く workflow も build しなかったので第3候補＝公開版 0.0.26 が当たり、そこに `delete` は無い（同じ変更で追加した未公開のサブコマンド）。回収対象が出た最初の実行で落ちる状態だったが、手元での端から端までの検証は全部通っていた。PR レビューで指摘されるまで検出されなかった。なお同じセッションの序盤に、公開版 CLI が `type: pipeline` を V031 で弾くこと（=公開版が遅れていること）を観測していた。その観測は「自分の計測を正しいツリーでやり直す」ことにだけ使われ、配布物が同じ遅れに当たるという読み替えが起きなかった。
  対策の追加: 検証はデプロイ先の解決を**再現して**行う。解決順を持つなら、本番が当たる候補を明示的に掴ませて1回通す（この例では公開版を `npm install` して環境変数で指し、起動時に停止することを確認した）。そのうえで、能力の有無を処理の入口で確かめて停止する — 対象が見つかってから途中で落ちる形にしない。
  対策: 外部実行物を導入するときは対象ホストごとの存在・権限・起動モードを列挙し、各ホストで最初の有意味な出力へ到達する smoke test を置く。代替起動モードを使う場合は適用する platform と隔離境界を明示し、その分岐を直接テストする。CLI transport の代替が必要な場合は、該当ステップを GitHub MCP のツール呼び出しで個別に置き換える（`.pfdsl/roadmap.md`「Open PR」節。恒久対策は #489）。
