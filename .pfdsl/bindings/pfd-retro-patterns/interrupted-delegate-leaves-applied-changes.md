- **中断した委譲先が適用済みの変更を残す trap**: subagent が途中で落ちたとき、返るのはエラーと部分ログだけで、そこまでに何をツリーへ適用したかは報告に含まれない。
  呼び出し元は「失敗した = 何も起きていない」と読みがちだが、実際にはコミット・ステージ済みのリネーム・未コミットの編集が残っており、再委譲すれば同じ変更を二重に当てる。
  問いの形: 「委譲先が中断したこの回、いま作業ツリーにあるものは誰が書いたか。報告ではなく `git status` / `git log` で数えたか」。
  具体例: 実装を委譲した agent がセッション上限で停止し、戻り値は「PARTIAL output」と末尾の一文だけだった。ツリーにはコミット1本・ステージ済みのリネーム4件・未コミットの変更6ファイルが残っており、呼び出し元は報告からは残作業を判定できず、`git status --short` と `git log --oneline` でどこまで進んだかを再構成した（2026-08-09）。
  対策: 委譲から戻ったら、成否によらず作業ツリーの状態を機械的に数えてから次の手を決める。再委譲・再実行の前に、適用済みの分を残作業から差し引く。
