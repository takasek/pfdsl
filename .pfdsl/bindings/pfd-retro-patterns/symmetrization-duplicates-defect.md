- **対称化が兄弟の欠陥を複製する trap**: 「同種のノードだけ形が揃っていない」型の作業項目は、揃える先の形を検証済みの正解として扱わせる。
  非対称の解消は目に見えるので達成感があり、揃えた形自体が目的を満たしているかは問われないまま複製される。
  兄弟が多いほど「これだけの数が使っている形が誤りのはずがない」という圧力が働くため、数の多さが検証の省略を正当化する向きに効く。
  問いの形: 「揃える先の形は、それ自体で作業項目の目的を満たしているか。非対称の解消と目的の達成を、別々に確認したか」。
  具体例: `cli_release_*` の3ノードが版番号を持たない非対称を、兄弟9件と同じ `criteria: npm show @pfdsl/cli version が X を返す` へ揃えて解消した。ところが `npm show <pkg> version` が返すのは dist-tag `latest` であり、この criteria は最新版1件を除いて文字どおり偽である。非対称は消えたが「done の根拠を検証可能にする」という目的は達しておらず、検証不能な記述を3件増やしていた（#652。retro で検出し、全11件を `npm view <pkg> versions に X が含まれる` へ揃え直した）。
  対策: 揃える先の形を**実行する**。criteria・コマンド文字列・検査手順なら実際に叩き、期待どおりの結果が返ることを確認してから複製する。目視では「兄弟と同じ形である」ことしか確認できない。
  この trap を後続 issue へ切り出して閉じるのは、対策の撤回を運用規律の追加へ翻訳する形になる — 揃え直しは同じサイクルで行う。
