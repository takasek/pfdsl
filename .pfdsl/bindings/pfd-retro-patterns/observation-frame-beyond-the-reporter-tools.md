- **報告の観測枠に、その道具立てでは確かめられない主張が入る trap**: 委譲先に「原因の推測は別枠へ」と要求しても、分けられるのは原因を名乗る文だけである。
  原因の形をとらない主張 — 出力がどう見えるか、実行するとどうなるか — は観測枠に残り、その agent が実際には観測していないまま観測として読まれる。
  問いの形: 「この報告の観測枠にある主張のうち、渡した道具立てで実際に確かめられるのはどれか。確かめられない主張は、原因を名乗っていなくても推測である」。
  見分け方は文の形でなく、agent に渡した道具と入力を数えること。ファイルを1つ読むだけの agent は、そのファイルの**内容**を観測できるが、そのファイルが**どう描画されるか**は観測できない。
  具体例: 生成後の `packages/cli/README.md` だけを渡した体験レビュー agent が、「code span 内の `\|` は backslash が残って描画される」を観測枠に書いた。
  文は原因を名乗っておらず、CommonMark の code span 規則を引いた見た目の指摘として観測と地続きに並んでいた。
  実際にはこの agent はレンダラを1度も通しておらず、主張は仕様文からの推論だった。
  GitHub の `/markdown` API に同じテーブルを通すと backslash は除去される — GFM はテーブルセル内の `\|` をコードスパン内も含めて escape として扱う。
  具体例: 配布 bundle から3ファイルだけを抜き出して渡した体験レビュー agent が、監査項目の参照先ファイルに到達できず「その一次情報が bundle に無い」を詰まりとして観測枠に書いた。
  ファイルが渡した集合に無かったことは事実の観測であり、agent の道具立てで確かめられる。
  確かめられないのは、それが実物の bundle でも起きるかのほうで、実物には当該ファイルが同梱されている。
  **抜き出した部分集合が実物と違うと、その差から生まれた詰まりが実物の欠陥として観測枠に入る。**
  渡す集合を手で選ぶ限り、選び方の誤りは agent 側からは見えない。
  観測と推論を地の文で混ぜる形（`observed-symptom-vs-inferred-cause`）と同じ被害だが、あちらは**原因**の枠に掛かり、こちらは原因を名乗らない主張が枠の網を素通りする経路である。
  対策の追加: 体験レビューに渡す材料は手で選ばず、実物の同梱マニフェストから導く。手で選ぶ回は、報告に出た詰まりの参照先が渡した集合の外にないかを採用前に確かめる。
  対策は採点側に置く。委譲ブリーフの合否判定要件（実物で採点し自己申告にしない）を、合否を伴わない所見にも広げる — 報告の観測枠にある主張を採用する前に、それを出せる道具を agent が持っていたかを1件ずつ照合し、持っていなかったものは実物に当ててから採用する。
