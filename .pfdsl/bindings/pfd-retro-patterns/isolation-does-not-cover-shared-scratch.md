- **隔離機構の外側にある共有スクラッチ trap**: 並行セッションの干渉対策として worktree を切っても、隔離されるのはリポジトリのツリーだけで、`/tmp` のような**リポ外の書き込み先は全セッションで共有されたまま**である。
  外部コマンドへ長い本文を渡すとき（`gh pr create --body-file` 等）に固定名の一時ファイルを使うと、書いてから読ませるまでの間に別セッションが同じ名前へ書き、相手の内容が自分の名前で公開されうる。
  worktree を切った時点で「並行セッション対策は済んだ」と分類されるため、この経路は対策の枠外にあると認識されない。
  書き込みも読み出しも成功し、内容の取り違えは公開後にしか現れない。
  問いの形: 「このサイクルでリポの外に書いたパスはどれか。そのパスは worktree 名・PID・乱数のいずれかでセッションごとに分かれているか、それとも全セッションで同じ名前か」。
  具体例: PR 本文を `/tmp/pr-body.md` に書いて `gh pr create --body-file` へ渡した回。PR 作成の直後、同じリポの別 worktree で走っていたセッションが同じパスを別の PR 本文で上書きし、こちらのファイル内容が入れ替わった（2026-08-10）。作成済みの PR は無事だったが、書いてから渡すまでの間に上書きが入っていれば、他セッションの本文で PR が公開されていた。
  対策: リポ外の一時ファイル名にセッション固有の要素（worktree 名等）を含める。渡す直前に内容を読み直して自分が書いたものか確かめる手もあるが、窓を狭めるだけで塞がらない。
