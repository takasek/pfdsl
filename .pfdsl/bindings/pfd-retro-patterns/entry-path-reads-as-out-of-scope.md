- **起動口を名乗る手順見出しが、別経路で入った実行主体に読み飛ばされる trap**: スキルの手順本体が特定の起動口（slash command 名）で見出し付けされていると、別の経路（bare issue 番号・skill の直呼び）で入った実行主体は、その節を自分に該当しないものとして飛ばす。
  description 側が両経路を同じ手順へルートしていても、本文の見出しがそれを打ち消す — 読み手が参照するのは本文であり、自分を起動した description ではない。
  飛ばされた節に他の手順が埋め込まれている場合、被害は節1つに留まらない。
  問いの形: 「この手順節の見出しは、手順の内容でなく特定の起動口を名乗っていないか。その起動口を通らずに入った実行主体が『自分は該当しない』と読める余地があるか」。
  具体例: 「#840 直して」で pfd-ops を直起動した回（2026-08-11）。`SKILL.md` の該当見出しは「ワークサイクル（/pfd-cycle の手順）」で、`/pfd-cycle` を起動していない実行主体はここを飛ばした。飛んだ先の手順1（選択）にはプリフライト集約スクリプトの実行が埋め込まれており、そこが出す設計記録テンプレートと、companion の「着手前の選択記録」規約にも到達しないまま実装へ進んだ。design-selection record は終端ゲートが FAIL を出してから投稿することになり、その時点でコミットは既に存在したためタイミング判定は原理的に回復不能だった（同型の結末が `duplicate-self-check-tool` にも記録されているが、そちらの原因は版ずれでこちらは経路差）。
  対策: 手順節の見出しは起動口でなく内容で名乗らせ、起動口を書く場合は経路を全て列挙する。
  経路が分岐しても必ず通る位置（プリフライト・前提条件節）から手順本体を参照させるのも同じ効果を持つ。
