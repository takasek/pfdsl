- **probe が見つけた欠陥の修正を委譲するとき、probe の場面が受け入れ条件から落ちる trap**: probe は特定の環境（配置形態・CLI の版・作業ディレクトリ等）で欠陥を見つける。
  修正を委譲するブリーフは欠陥の説明から書かれ、「どの環境で起きたか」は背景として一度触れるだけになりがちである。
  委譲先は説明に合う最も素直な実装をし、自分が書いたテストを通して完了を報告する。
  その実装が probe の環境に届いていなくても、テストは委譲先が想定した環境しか見ないので緑になる。
  問いの形: 「この修正の受け入れ条件に、欠陥を見つけた probe の環境そのもの（配置形態・入力・作業ディレクトリ）での再実行が入っているか」。

  観測（2026-09-30、PR #1321 の distribution review）: probe P3 は plugin 構成（`installation: claude-plugin`）の採用リポで、報告用の環境収集がリポで固定した CLI の版を報告しないことを見つけた。
  修正のブリーフは「リポの `package.json` が `@pfdsl/cli` を宣言していれば `repoCliVersion` を報告する」と書き、環境については P3 の状況を説明に添えただけだった。
  委譲先は、収集スクリプトが既にリポのルートを知っている構成（repo-local / upstream-checkout）でだけ読む実装をし、テスト7件を通して報告した。
  plugin 構成ではリポのルートが空になるため、項目はそもそも出なかった。

  証拠: 委譲先自身が報告の「呼び出し元の判断が必要」の節で、plugin 構成に届かないことを書いていた（`8e63e4ad`）。
  作業ディレクトリから採用リポを決める拡張（`a47d9b17`）の後、P3 の sandbox で実際に走らせて `repoCliVersion: 0.0.26` が出ることを確かめた。

  採用した対策: 拡張のブリーフには「P3 の sandbox から実際に走らせ、installation と repoCliVersion の行を報告する」を受け入れ条件として入れ、効いた。

  原因の仮説（未検証）: 欠陥の説明は「何が足りないか」を書くので、「どこで足りないか」は受け入れ条件に翻訳されないまま背景に残る。

  未解決: 報告に「呼び出し元の判断が必要」の節が無い委譲先なら、同じ欠落は完了報告として素通りする。
